# 补仓、锁仓期特批、每日历史与备份

## 使用

- 批次与单客户机构补仓均默认补股票，可切换现金。股票数量 = 本次等值金额 ÷ 当前计价；不修改客户原始本金，机构保留其本金及收益。系统记录到账股票，不会替代券商划转或真实交易。金额按美分，股数按计算精度记账，页面显示 6 位小数。
- 管理员或风控总监可在锁仓期点击「锁仓期特批退出」，先确认锁仓风险，再核对结算明细。原有手续费、资产充足、历史账本完整性校验保持有效。服务端核验角色及确认记录，操作留痕。
- 批次详情新增「批次历史」：曲线、每日表格、某日明细和 Excel 下载。补仓日显示现金／股票、等值金额、股数和计价。表格和曲线读取同一份数据库快照，不依赖浏览器缓存。
- 管理员进入「系统设置 → 数据备份」，填写收件邮箱（最多 5 个），选择每天／每 7 天／每 30 天发送。关闭邮件不关闭每日备份。页面提供最近 14 份备份下载及邮件受理状态。

## Vercel 上线

1. 代码构建使用原有 `npm run build`，依次 Prisma generate、migrate deploy、Next build。新增迁移 `20261113_daily_history_backups`，建立 `BatchDailySnapshot` 和 `BackupArchive` 两张表，不修改旧账本。
2. 设置独立随机的 `BACKUP_KEY`（至少 32 字符）和 `CRON_SECRET`，保留数据库、登录和已验证的邮件服务环境变量；重新部署。`BACKUP_KEY` 必须单独离线备存，丢失后无法解密；不要更换后丢弃旧密钥。
3. `vercel.json` 注册 `/api/internal/daily`，`0 0 * * *`（UTC）即北京时间 08:00。Vercel 通过 `Authorization: Bearer CRON_SECRET` 调用。生产定时任务执行时间受套餐调度精度影响。该任务与已有高频风控监控分开，不替代闪跌监控。
4. 后台开启邮件前先检查「最近定时执行」出现真实记录及「最近备份」已有文件。启用邮件后，到下一次计划任务执行时发送。邮件受理不代表送入收件箱，请验证收件箱。
5. 邮件附件支持 Resend、Postmark、SendGrid；自建 EMAIL_WEBHOOK_URL 必须处理 `attachments` 数组（filename/content/base64/contentType）并传递附件。只转发正文的旧 webhook 不具备备份能力，不应启用备份邮件。

## 每日历史的口径

- 当前系统标的为美股，使用 America/New_York 交易日，自动处理夏令时；每日任务在常规交易结束后取当日日 K 线收盘价。无当日真实行情时不复制昨日价格、不生成模拟收盘价。
- 业务持仓／客户状态按采集时刻冻结，收盘价按行情源当日日 K 线；页面显示采集时间与来源。盘后发生的业务操作可能包含在当次采集中。
- 同批次同交易日仅生成一次；重复调度不会覆盖历史。启用前没有留存的旧日数据不使用当前持仓倒推。未运行或行情不可用会留下空缺，需人工核对，不能据此认为当日无风险。
- 当天补仓事件按纽约日期汇总，保留多次补仓明细。现金余额及持股数为未结算余额，累计盈亏包含已实现及未实现。

## 备份内容与可靠性

- RepeatableRead 数据库一致性快照，包含所有应用表：账户、会话、业务账本、客户、补仓、结算、配置、每日历史、行情、审计和通知等。备份归档表本身不递归装入备份。
- JSON 经 gzip 压缩，再 AES-256-GCM 加密，随机 salt/IV、独立派生密钥，SHA-256 校验归档。备份附件无密钥、无明文登录或数据库凭据。归档保存在数据库，邮件附件提供异地副本。
- 按北京时间每日生成一份，邮件可按周期发送最新完整归档，完整归档包括全部已留存历史。只使用服务端落库数据，浏览器尚未同步的内容不在备份中。
- 邮件逐收件人记录受理状态，已受理者不重复发送。明确失败最多自动尝试 3 次，超时或发送进程中断标记待核查，不盲目重发。新的计划日会发送新的完整备份。
- 大于 7 MiB 的归档仍在数据库保留，但不通过邮件发送；后台明确提示，管理员可下载，并需接入外部对象存储或数据库原生备份。
- 当前不自动清理归档；需要按实际数据量监测数据库容量。数据库内归档不能代替数据库服务商的灾难恢复，建议同时开启托管数据库原生备份。

## 验证与恢复（运维）

下载 `.rcbackup` 后，使用创建该备份时的密钥：

```sh
BACKUP_KEY='原备份密钥' npm run db:restore-daily -- /secure/riskcontrol-YYYY-MM-DD.rcbackup
```

默认仅解密校验并显示各表行数，不写数据库。恢复前对一个**新的空数据库**执行同版本 schema 迁移，然后设置 `RESTORE_DATABASE_URL` 和 `RESTORE_CONFIRM_DATABASE`（精确目标库名），加 `--restore`：

```sh
npm run db:restore-daily -- /secure/riskcontrol-YYYY-MM-DD.rcbackup --restore
```

恢复拒绝同源数据库、拒绝非空目标库；认证校验完成后才开始写入，全过程事务提交。不会恢复旧的有效登录会话和限流状态；业务数据与历史、审计、通知状态恢复。恢复完需审查邮件收件人、定时任务、渠道及环境变量，再开放新环境。

`npm run db:backup` 原有 pg_dump 工具仍保留，用于数据库原生全量加密备份，格式与每日 JSON 归档不同，不能混用恢复命令。
