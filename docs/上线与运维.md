# 上线与运维

覆盖服务器部署所需的四件事：上线自检、数据库迁移与账号初始化、加密备份/恢复、服务端闪跌监控。
本地开发与演示配置见 README，通知渠道细节见《机构记账与通知配置》。

## 一、环境变量

复制 `.env.production.example` 为 `.env` 后填真实值。该文件含密钥，不要提交版本库。

| 变量 | 要求 |
| --- | --- |
| `NEXT_RC_AUTH_SECRET` | ≥32 字符（`openssl rand -hex 32`）。生产缺失直接启动失败 |
| `DATABASE_URL` | 必填，指向服务器本机 PostgreSQL |
| `RC_ENABLE_DEV_MOCK_ACCOUNTS` | 生产必须为 `0`，内建演示账号只在开发环境可用 |
| `RC_ALLOW_SEED` | 默认 `0`；仅首次初始化账号时置 `1` |
| `RC_SEED_PASSWORDS` | 逐账号口令 JSON，长度 ≥12。未列出的账号不创建 |
| `RC_SEED_FORCE_PASSWORD` | 默认 `0`；仅在需要重置既有账号口令时置 `1` |
| `EMAIL_WEBHOOK_URL` / `WHATSAPP_WEBHOOK_URL` | 至少一个为真实地址，否则预警发不出去 |
| `NOTIFICATION_SEND_TOKEN` | 通知发送授权码，`openssl rand -hex 32` |
| `RC_MONITOR_INTERVAL_SEC` | 监控轮询间隔秒数，默认 30，下限 5 |

## 二、上线自检

```sh
npm run preflight
```

生产环境缺关键项直接失败退出（fail-closed）。已有账号资料不会被覆盖，模板占位值（`your-*`、`CHANGE_ME`、`example.com`）一律视为未配置，避免自检出现“假通过”。

## 三、数据库迁移与账号初始化

- 迁移：`npm run db:migrate`（等价 `prisma migrate deploy`）。脚本在 `prisma/migrations/`，已应用的不要重复执行；生产不要用 `db:push`。
- 账号初始化是一次性动作：把 `RC_ALLOW_SEED` 置 `1` 并提供逐账号 `RC_SEED_PASSWORDS`，重建容器创建账号，完成后改回 `0`，避免每次重启重放 seed。
- 容器启动顺序：`migrate deploy` → 条件性 `db seed` → `preflight` → 启动服务（见 Dockerfile CMD）。
- 口令存储：PBKDF2-HMAC-SHA256，210,000 次迭代。历史 SHA-256 摘要在登录成功时自动升级，不需要重置口令。

## 四、加密备份与恢复

主机需安装与服务端版本兼容的 `pg_dump`、`pg_restore`、`psql` 并加入 PATH。

```sh
# 备份（BACKUP_KEY ≥32 字符，另存密钥管理服务，不随备份上传、不提交 Git）
npm run db:backup -- /secure/offsite/ledger-20261027.rcbackup

# 恢复（RESTORE_DATABASE_URL 指向独立空库，RESTORE_CONFIRM_DATABASE 填该库精确名称）
npm run db:backup -- restore /secure/offsite/ledger-20261027.rcbackup
```

- 备份：`pg_dump --format=custom` 一致性快照 → AES-256-GCM 加密 → 0600 权限；拒绝覆盖已存在文件，写入失败不会留下半成品文件。
- 恢复：先完整校验密文与认证标签，再接触目标库；拒绝与源库同地址同端口同名、拒绝非空库、要求确认名精确匹配。恢复在单个数据库事务内执行，失败整体回滚。
- 本命令只负责“备份文件”与“目标库”两件事，不自动创建异地存储、调度、保留策略或容量监测，这些需另行配置。
- 恢复账号应限权于专用空库；恢复后须逐表比较记录数并核对客户持仓与审计记录，本地演练不能替代生产演练。

已完成的演练结论（PostgreSQL 16.14 实测）：错误密钥在接触目标库前被拒绝；错误确认名被拒绝；正常恢复后表数量与 `AppUser` 行数一致；非空库被拒绝。

## 五、服务端闪跌监控

行情采集与闪跌检测独立于浏览器运行，关闭页面不影响监控。单机试点与 Web 服务共用镜像。

```sh
docker compose up -d --build                # 含 db / app / monitor 三个服务
RC_MONITOR_ONCE=1 npx tsx scripts/flash-monitor.ts   # 只跑一轮，用于部署自检
```

- 行情落库为价格历史，告警按去重键持久化，投递状态可追踪并重试；已投递的不会重复发送。
- 单轮异常只记录日志、不退出常驻进程；进程自身停机需由编排平台的重启策略与外部探针发现。
- 面板上行情会标注来源（实时 / 最近成功缓存 / 缓存已过期 / 离线占位）与时间戳。

## 六、行情有效性

关键风险决策（如建仓）拒绝使用超过 10 分钟 TTL 的行情，过期时提示手动输入或稍后重试，不会静默按旧价建仓。

## 七、回归验证

```sh
npm run verify:hardening      # 资金写入识别、闪跌核心判定、冲突快照跨客户脱敏
npm run verify:finance        # 财务引擎：损益冻结、归属隔离、补仓分配
npm run verify:notifications  # 通知通道配置与投递语义
npm run verify:test-data      # 测试数据规模与隔离
npm run build                 # 生产构建
npm run verify:preview        # 需先启动服务，校验页面与静态资源
```
