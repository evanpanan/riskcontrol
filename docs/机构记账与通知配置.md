# 机构记账与通知配置

## 产品边界

当前产品仅登记机构补仓和结算，不在券商下单，不划转资金。
补仓操作是按登记价格记录的机构出资，未来接入券商前不能等同实际成交回报。
`src/lib/brokerSync.ts` 仅预留只读适配器契约，当前没有注册实现或启动同步任务。

未来同步应先进入待核对区，不得直接调用按缺口截断金额的手工补仓函数。
必须按机构、券商账户、成交 ID 去重；校验批次、轮次、标的、币种、成交价、
份额、手续费及机构归属。外部金额超过缺口、部分成交、更正/撤销、分页重试及
手工记录重复均需对账，已结算轮次禁止自动改写。确认后再在服务端事务中记账。
券商凭据只存服务端，适配器不提供下单或转账接口。

## 最简通知配置

1. 管理员在服务器设置以下环境变量，重启应用。
2. 在「系统设置 → 通知渠道配置」点击「检查服务配置」。
3. 输入管理员提供的发送授权码，点击「启用本次发送授权」。
4. 输入真实邮箱或含国家区号的 WhatsApp 号码，保存，点击对应测试按钮。
5. 核对实际收件后再添加/启用正式收件人。没有预置示例收件人。

授权码使用 `openssl rand -hex 32` 生成，配置为 `NOTIFICATION_SEND_TOKEN`。
此命令应由部署管理员执行，不要将结果提交到 Git。
前端只在当前页内存暂存授权码，刷新后重新输入；API Key 不进入浏览器。
这是当前本地登录架构的过渡保护，不能代替生产多租户服务端鉴权。
部署公网前需要服务端登录权限、共享限流、持久化审计、幂等发送和投递回执。

### 邮件（推荐 Resend）

- `RESEND_API_KEY`：Resend API Key。
- `NOTIFICATION_FROM_EMAIL`：已在服务商验证域名的发件地址，例如 `RiskControl <notice@机构域名>`。
- 设置页的 Email Webhook 留空，填真实收件人。
- 也支持 `POSTMARK_SERVER_TOKEN` 或 `SENDGRID_API_KEY`，选择一种即可。

### WhatsApp（推荐 Twilio）

- `TWILIO_ACCOUNT_SID`、`TWILIO_AUTH_TOKEN`：服务器凭据。
- `TWILIO_WHATSAPP_FROM_NUMBER`：获准使用的 WhatsApp 发件号码，含国家区号。
- `TWILIO_WHATSAPP_CONTENT_SID`：审核通过的模板，正文有一个变量 `{{1}}`，传入通知内容。
- 接收者必须授权订阅；沙箱收件人需先加入沙箱。主动风险提醒不依赖24小时会话窗口。
- 不会退回普通 SMS 发送，不会在失败后自动换渠道重试。

Meta 直连可配置 `META_WA_ACCESS_TOKEN`、`META_WA_PHONE_NUMBER_ID`、
`META_WA_TEMPLATE_NAME`、`META_WA_TEMPLATE_LANGUAGE` 和当前受支持的
`META_GRAPH_API_VERSION`。同样要求审核模板的正文有一个文本变量。

### 已有 Make / n8n 自动化

在服务器设置 `EMAIL_WEBHOOK_URL` 或 `WHATSAPP_WEBHOOK_URL`，优先于直连服务商。
只使用可信 HTTPS 地址；设置页留空即可。填写地址时必须与服务端授权地址完全一致。
请求包含 `channel`、`to`、`subject`、`title`、`message`、`body`、`text`、`html`、
`severity`、`type`、`batchId`、`details`。
自动化流程应返回 `{"success":true,"sentTo":["实际受理的收件人"]}`；
业务失败返回 `success:false`。仅 HTTP 2xx 且无业务回执时，只能证明流程已接收请求。

## 结果含义

- 当前外部通知由按钮触发；网页风险弹窗不会自动发送邮件或 WhatsApp。
- 「已受理」不等于「已送达」，最终以服务商回执和实际收件为准。
- 部分失败显示已受理名单及失败原因，不自动重发整批。
- 网络中断或超时可能已经受理，先查服务商记录再决定是否重发。
- 本地日志保存失败不会伪报服务商发送失败。
- 没有真实凭据时只能验证配置校验和模拟服务商测试，不能宣称真实送达已验收。
