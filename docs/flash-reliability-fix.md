# 闪跌监控可靠性修复

部署前执行 `npm ci` 和 `npm run db:migrate`，再部署应用与监控任务。不要在未迁移数据库时运行新版任务。

- Yahoo/Finnhub 保存行情真实时间，采集时间单独记录。服务端只接受过去两分钟内的行情，允许最多30秒时钟超前，并在拒绝某行情源后尝试下一源。Nasdaq/Stooq 的时间格式尚不能可靠判定时区，保留未知时间0，不能用于实时闪跌判定。闭市、停牌、延迟行情会跳过并在任务 notes 中说明；不将旧收盘价当成实时价。
- 失败告警没有一小时截止窗口，每分钟重试。即使无批次、阈值关闭、行情全部失败也继续处理已有告警。按下次重试时间排序，每轮最多50条。
- 每个渠道成功后立即保存 sentChannels，重试跳过成功渠道。数据库原子领取10分钟租约，防止常规并发任务重复处理。进程崩溃后租约到期可继续。

验证：`npx tsc --noEmit`、`npx tsx scripts/check-flash-reliability.ts`、`npm run verify:notifications`。

限制：供应商已受理但响应丢失、或成功后数据库写入失败时，仍可能重发；跨外部服务的严格一次投递需要供应商幂等键支持。旧版部分发送记录没有分渠道状态，无法自动推断历史成功渠道。持续失败保持待重试并记录 deliveryNote，不丢弃告警。尚未对真实生产数据库或真实通知服务执行验证。
